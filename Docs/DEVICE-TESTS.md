# 실제 기기 인수 테스트 — 아직 실행하지 않음

장치 A=iPhone, B=iPad, C=Mac. 모두 같은 Apple 계정/동일 CloudKit 컨테이너/동일 Development 또는 Production 환경을 사용합니다. Mac의 로컬 전용 스킴과 Cloud 스킴을 혼동하지 마세요. 앱 데이터 삭제/컨테이너 reset 없이 진행합니다. 완료 판정은 실제 화면/재시작 결과이며 상태 문구만 보고 판정하지 않습니다.

## 준비/빌드

- [ ] README의 Team ID, 두 bundle ID, 컨테이너 enrollment, Push/iCloud 권한을 설정합니다.
- [ ] `bash Scripts/build-apple.sh local`로 iOS Simulator 및 Mac Apple SDK 컴파일을 확인합니다.
- [ ] `bash Scripts/build-apple.sh test`로 3개 SwiftData 저장소 테스트를 실행하고 `logs/apple-persistence-tests.log`와 xcresult를 보관합니다.
- [ ] A/B는 PhaseSystemCloud, C는 PhaseSystemMacCloud로 실행합니다. iCloud 계정 사용할 수 없음/서명 오류를 해결한 뒤 진행합니다.

## A → B → C 실제 전파 / 단일 기록의 여러 관점

- [ ] A에서 Area `연구`와 Phase `탐색`을 만듭니다. Phase 목표/현재/병목/기대 변화/자료/메모를 각각 다른 값으로 저장합니다.
- [ ] A에서 일반 작업 G(탐색 소속), 빠른 작업 Q(탐색 소속), 미소속 일반 작업 U를 만듭니다. 일반/빠른 구분이 소속과 무관한지 확인합니다.
- [ ] A에서 G/Q/U를 차례로 Spotlight ON하고 U/G/Q로 드래그 재배열합니다. B/C에서 작업 내용과 **같은 순서**를 실제 확인합니다. Q OFF 후 원본 Tasks에 남고, 다시 ON하면 맨 아래인지 확인합니다.
- [ ] G에 Done `조사 수행`, 메모 `짧은 메모`, 다음 시작 `두 번째 문헌`을 저장합니다. 작업/Phase/Area/그 날짜 Daily Log에 동일 기록이 보이고, 전체 Markdown에는 그 본문이 한 번만 나오는지 확인합니다.
- [ ] B에서 G에 새 Done을 다음 시작 빈칸으로 저장합니다. A/C에서 예전 `두 번째 문헌`이 사라지고 최신 수행 본문이 Resume가 되는지 확인합니다. Q의 다음 시작은 독립적으로 유지되어야 합니다.
- [ ] C에서 오래된 기록을 본문만 수정합니다. 수정 시각 때문에 최신 수행/중립 한 달 표시 순서가 바뀌지 않는지 확인합니다. 수행일을 의도적으로 정정하면 그 날짜로 이동해야 합니다.

## 네트워크 끊김/종료/재실행

- [ ] A를 비행기 모드(네트워크 완전 차단), C도 네트워크 차단합니다. A에서 새 Done/다음 시작 교체와 Spotlight 재배열, C에서 **다른 작업**에 Done 및 Inbox 자유 텍스트를 만듭니다.
- [ ] 양쪽 앱을 완전히 종료 후 오프라인 상태로 재실행합니다. 방금 저장한 내용/별 순서/다음 시작/인박스가 유지되어야 합니다. 빈 화면/메모리 전용 fallback은 실패입니다.
- [ ] 네트워크를 복구하고 앱을 활성 상태로 둡니다. B를 포함해 A/C의 서로 다른 항목이 모두 전달되는지 실제 확인합니다. OS 스케줄링에 따라 지연될 수 있으므로 지연 시간/CloudKit event 오류도 기록합니다. 단순 재조회는 업로드 강제가 아닙니다.
- [ ] B 오프라인에서 Inbox 항목을 편집한 뒤 A에서 해당 Inbox를 삭제합니다. B 연결 복구 시 동일 항목 충돌 정책(timestamp 기반 전체 항목 승자)을 확인합니다. 삭제보다 **이전** revision을 뒤늦게 받아도 살아나지 않아야 합니다. 삭제 이후 더 늦은 오프라인 편집은 승자가 될 수 있습니다.
- [ ] 같은 작업을 A/C에서 동시에 서로 다른 내용으로 편집해 전체 항목 LWW가 수렴하는지 확인합니다. 내용 합치기를 기대하지 않습니다. 동시 Spotlight 재배열 후에도 세 장치가 결국 같은 결정적 순서로 수렴하는지 확인합니다.

## 의미/UI 확인

- [ ] G를 새 Phase로 이동해도 이전 Done/완료/중단 사건은 이전 Phase/Area에 남는지 확인합니다.
- [ ] 완료와 중단이 다른 이력으로 남고, 기본 Tasks/Spotlight에서 숨겨지며, 다시 열어도 별이 자동 ON되지 않는지 확인합니다.
- [ ] Phase/Area 보관이 작업을 이동/종료하지 않는지, 보관 항목 보기와 재개가 되는지 확인합니다.
- [ ] 한 날짜에 여러 Done을 넣어도 같은 한 칸, lifecycle-only 날짜는 칸 없음, 기록 없는 날짜 입력 의무/연속일 점수가 없는지 확인합니다.
- [ ] 작업 없는 Done, 자정 근처 수행일 정정, 다른 시간대 기기에서 현지 날짜 표시를 확인합니다. 날짜는 저장된 절대 시각을 각 기기의 현재 달력/시간대로 묶습니다.
- [ ] 모든 탭/상세에서 떠 있는 +가 분류 없는 Inbox이며 저장/취소가 현재 탐색 경로로 돌아오는지 확인합니다.
- [ ] 저장 실패 주입 테스트의 rollback/retry 외에 실제 저장 공간/파일 권한 오류 발생 시 보이는 오류, 편집 초안 보존을 확인합니다. 사용자 데이터 삭제로 실패를 재현하지 마세요.
- [ ] Markdown 내보내기에 보관/종료 항목·전체 국면 필드·날짜 있는 Done/메모·인박스가 있고 내부 UUID/순서 값/현재 다음 시작점은 없는지 확인합니다. export 취소가 정상인지도 확인합니다.
- [ ] `Tests/UIAcceptance.md` 전체를 iPhone, 넓은 iPad, Mac 키보드/VoiceOver에서 확인합니다.
